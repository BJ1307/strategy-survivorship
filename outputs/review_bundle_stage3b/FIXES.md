# 本轮修复记录

## 1. 中位检测时间的定义

**问题.** `stage3a1._summary` 取的是**已报警样本**的中位数，并以 `k > n/2` 为门。
这不是总体中位检测时间：一条从不报警的路径不是缺失数据，而是一个大于期限的
检测时间，必须留在分母里。

**修复.** 全项目改用同一个定义——全部路径的累计报警比例首次达到 1/2 的那一天，
恰好达到 1/2 也算达到；未达到则如实标记。项目里 `stage2c.metric_row` 原本已有正确
实现，因此把它抽成 `evaluate.median_first_passage_day`，两处共用，不再维护第二份。

**核验.**

| 样例 | 正确值 | 旧实现给出 |
|---|---|---|
| 100 条路径，60 条分别在第 1–60 天报警，其余未检出 | 第 50 天 | 30.5 |
| 100 条路径，50 条分别在第 1–50 天报警 | 第 50 天 | NaN |
| 100 条路径，49 条分别在第 1–49 天报警 | 未达到 | NaN |

**影响范围.** 用**原始随机流与冻结门槛**重建 Stage 3A.1 后，逐列比对 23 列 × 256 行：
只有 `median_first_alarm` 与 `median_note` 两列改变。
`stage3a1_thresholds.csv` **逐字节相同**，证明没有重新选择门槛；
检出率、误杀率、`E[min(τ,H)]` 及全部差异均未变。
修正后的表在 `data/stage3a1_metrics_median_fixed.csv`。

## 2. 无效的自比较测试

**问题.** `test_the_two_arrangements_coincide_at_the_calibration_horizon` 里写的是
`assert thr[k] == thr[k]`，对任何字典恒真，什么都没检查。

**修复.** 改为运行 `evaluate` 的两条**实际评价分支**，在 H=504 处比对
threshold / detect / far / `E[min(τ,H)]` / 未检出 / 工作概率门槛（atol=0），
并核对两臂的报警时间数组逐元素相同；另加一条反向测试，确保 H=126 处两臂**确实不同**，
以免同样的失效模式再次通过。

## 3. 期限比较的措辞

- 「同样代价下，两年更划算」→「**相近累计误杀率下，更长观察期获得更高累计检出率**」，
  并明确写出**等待成本未纳入评价**：多监测一年半意味着无效策略继续运行、继续占用资金与
  风险额度，这些不在检出率与误杀率两个指标之内。
- 「半年不能发现多数」→ 限定为「**在本轮测试的四个方法与两个情境下**」，
  并说明这不是关于所有可能检测规则的一般结论。

## 4. 本轮新发现并修正的两处

- **图 3 的尺度错误.** 曾把 252 日 trailing Sharpe 放进「工作失效对数赔率」诊断，
  但它的统计量是年化 Sharpe 比率，不在对数赔率尺度上，对它取 `expit` 没有可解释含义。
  该诊断已限定为四个对数赔率方法，并在表与图中写明原因。
- **表头里的竖线.** `E[min(τ−T,252)|τ>T]` 中的 `|` 会打断 Markdown 表格。
  已改写，并把自动检查从固定文件名列表改为 glob 全部 `stage*_report.md`，
  确保今后新增的报告也被覆盖。
